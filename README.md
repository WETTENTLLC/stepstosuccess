## Stack
- Static HTML5 + CSS (custom properties design system) + minimal vanilla JS. No frameworks, no WordPress files, plugins or old credentials.
- Staging/app server: Node (no runtime dependencies), `server.js`: security headers + CSP, optional Basic auth, server-side form handling, donation hand-off, redirects.
- Card data never touches this server: donations redirect to a hosted checkout (not yet connected). Secrets live in environment variables / `.env` (git-ignored).

## Run
```
npm run build    # generates public/ pages from src/ (edit src/, never the generated HTML)
npm start        # builds, then serves http://localhost:3000
```

## Structure
```
src/
  layout.html         Shared head, header/nav, footer (logo, disclosures)
  pages/*.html        Page sources: home, our-story, programs, senior-moments, impact, donate, partners, contact, privacy, accessibility
                      (first line is a meta comment with slug/title/description; "_" files are skipped)
build.js              Assembles layout + pages into public/ (SITE_URL env sets canonical base)
public/
  **/index.html       GENERATED pages
  404.html            Served with a real 404 status
  css/styles.css      Design system v2: tokens, type scale, buttons (primary/secondary), cards, photo frames, draft badges
  js/enable.js        Adds .js class (menu collapses only when JS runs)
  js/nav.js           Menu toggle: aria-expanded, Esc closes + returns focus, focus-out closes
  img/logo.png        Header logo (cropped/resized from the supplied original)
review/
  check.js            Automated checks (status codes, overflow at 5 widths, nav/keyboard, no-JS, 200% text, reduced motion)
  screenshots/        Output of the checks
server.js             Dev static server with security headers (404 status for missing pages)
```

## Run and check

## Photograph workflow
Authentic photos only (Facebook archive first; historical site and press as supplements). No AI-generated people.
```
assets/originals/<category>/   untouched originals (NOT served)
assets/photos.json             event, approxDate, caption, alt, source, people, permission
public/images/<category>/      optimized WebP (640/1280/1920px) generated by `npm run photos`
```
Categories: branding, leadership, homepage, programs, senior-moments, success-stories, galas-awards, partners. Only `permission: "approved"` entries are processed. Participant and senior photos need explicit consent for use on this new site. Third-party press photos (e.g. the 2019 NAILS Magazine article) are copyrighted: link to the article, or get written permission from the publisher/photographer before reusing the images. Suggested placement: homepage hero (Delane and Myeshia with participants), Our Story (portraits, early events), Programs (training, mentoring, workshops), Impact (graduates, car presentations), Senior Moments (real outreach), Partners (galas, awards, sponsors). The logo stays in `public/img/`.

## Content rules
No invented stats, eligibility, services, deadlines or donation info. Anything unapproved is shown as a highlighted `.placeholder` or `[Approved ...]` bracket. Replace only with organization-approved content. Photos must be real, permissioned, compressed (WebP/JPG) with descriptive alt text.

## Open items needed from the organization
1. Approved mission statement, headline, history, leadership names/bios.
2. Verified legal name, status (e.g., 501(c)(3)/EIN), address, phone, email.
3. Real domain (replace `example.org` canonical) and registrar access confirmation.
4. Donation provider/account choice and approved giving options.
5. Program/scholarship eligibility, deadlines, application questions, and whether applications are open.
6. Old-site URL list for 301 redirects.
7. Authentic photos with consent.

## Photos and SEO (Milestone 2)

- Manifest: `assets/photos.json` (status: staging = awaiting identity/consent confirmation, hold = never published). Run `npm run photos` to copy originals to `assets/originals/` and write WebP files to `public/images/optimized/`.
- Use `{{photo:id|sizes=...|eager}}` in `src/pages/*.html`. Unknown ids fail the build.
- The dev server refuses to serve raw originals. At deploy, publish only `public/images/optimized/`, not the originals in `public/images/<category>/`.
- `npm run build` also writes `public/sitemap.xml` and a staging `public/robots.txt` (Disallow all). Pages stay `noindex` until launch approval. Set `SITE_URL` for real canonical URLs.
- JSON-LD (Organization on home, breadcrumbs on inner pages) is in `build.js`; its address and legal details are marked VERIFY.

## Milestone 3: forms, donations, security

### Environment variables (server.js)
| Variable | Default | Purpose |
|---|---|---|
| `PORT`, `HOST` | 3000, 127.0.0.1 | Bind address. A non-local HOST **refuses to start** without `STAGING_PASSWORD`. |
| `STAGING_PASSWORD` | unset | Enables HTTP Basic auth (min 12 chars). `STAGING_USER` defaults to `dnnc`. |
| `FORMS_MODE` | `disabled` | `disabled` = 503 + disabled buttons; `test` = validate and write to git-ignored `data/test-outbox.jsonl` (nothing is sent); `live` = not implemented until approvals and a mail provider exist. |
| `FORM_SECRET` | random per process | Signs anti-spam tokens. Set a long random value in production. |
| `FORM_MIN_AGE_MS`, `FORM_RATE_MAX` | 4000, 5 per 15 min/IP | Time-trap and rate limit. |
| `SITE_URL` | https://example.org | Canonical URLs (build time). |

### Forms (`lib/forms.js`, `config/forms.json`)
Contact, scholarship inquiry, volunteer, Senior Moments and corporate forms live at `/contact/<form>/` and post to `/api/forms/:id`. They work without JavaScript. Spam defenses: honeypot, signed single-use time-trap token, per-IP rate limit, Origin check, body/field limits, link-count limit. Only the minimum inquiry data is collected. `config/forms.json` holds recipients, privacy approval and retention, all unapproved.

### Donations (`lib/donate.js`, `config/donations.json`)
Frequency + amount selection posts to `/donate/start`, which redirects to a hosted checkout URL. `enabled:false` and no processor by default, so the button is disabled and the endpoint returns 503. Suggested amounts are DRAFT.

### Redirects
`config/redirects.json`: only verified entries are active; guesses stay inactive. `/wp-login.php`, `/xmlrpc.php`, `/wp-admin/`, `/wp-content/`, `/wp-includes/`, `/wp-json/` return 410.

```
npm run backup                 # verified git bundle in "DNNC STEPS BACKUPS (private)" beside the project
```
